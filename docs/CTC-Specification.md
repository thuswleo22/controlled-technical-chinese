# CTC 受控技术中文规范

CTC 表示 Controlled Technical Chinese。本合并版修订日期为 2026-11-18。

## 适用范围与证据

本规范适用于接口、架构、运维与安全文档。规则分为六个控制对象，每个规则只在一个主分类定义。领域专名、接口标识和实际测量的不确定性按项目语境保留。

本版合并 Carbon 草案中的指代、阈值、条件结构和工具接口设计，以及已有的词典审查、真值检验和原始语料实验。逐条采纳决定和规则编号迁移见[设计取舍](Design.md)。研究来源与发布范围见[来源说明](Sources.md)。

## 词汇与构词

### RULE-LEX-01 用「复制」表示生成数字副本的动作

用「复制」表示生成数字副本的动作。用「副本」命名生成的对象。检查器按本条的限定位置诊断动词「拷贝」。

检查器在正文中寻找「拷贝」。当其后紧接目的地标记「到」或「至」时，发出诊断。当前面是列表项开头、动作标签、明确的指令标记或受控主体，且后面出现受控数字对象或对象标记时，也发出诊断。受控主体包括操作员、管理员、值班员、客户端、服务器和处理器等。对象标记包括技术对象词、指示词、数词量词和行内代码。检查器忽略引文和代码内的「拷贝」。

违规示例。

```text
操作员拷贝配置文件。
```

合规示例。

```text
操作员复制配置文件。
```

17 个词汇样本中，限定位置的检查保留全部 7 个违规命中。与搜索全文词串相比，误报由 9 个降至 0 个。已标注的名词性用例用于核对动词限制的适用范围。更广的名词、副本类型和省略上下文需要术语审查。

### RULE-LEX-02 用「编码」作谓词

使用「编码」描述按指定格式转换对象的动作。对于单个子句中的「对〈对象〉进行编码」，用「编码」直接带对象。保留条件、编码格式及其他语义限制。

检查器在正文中匹配「对」和「进行编码」之间有非空对象的结构。范围止于逗号、句界和换行。词内的「对」及常见定语和专名后缀排除在检测范围外。仅诊断该结构中的「进行」。包含「编码器」「编码错误」等名词组合的用例按后缀排除。引用语和代码中的字样不触发规则。

违规示例。

```text
服务对响应进行编码。
```

合规示例。

```text
服务编码响应。
```

17 个词法样本中，限定子句的检查器检出 7 个违规结构，10 个对照均无诊断。全文检索基线产生 4 个误报。两条真实原句及改写的对照中，已标注动宾匹配从 1/3 增至 2/3，合计分词从 46 降至 41。完整三元组匹配仍为零。该证据支持对本结构的诊断。其他「进行」结构需要各自验证。

## 角色与指代

### RULE-REF-01 在受控步骤中分开写执行者和动作

需要机器读取的步骤使用「步骤」块。将执行者和动作分开。执行者应能按上下文确定。存在先决条件时，在执行者前列明条件。

在正文或列表项开头写「步骤」和冒号。后续字段行的顺序为「执行者、动作」或「条件、执行者、动作」。字段的值写在冒号后的同一行。空行、标题、新列表项或新块结束当前步骤。引用或代码中的标签不参加判定。字段缺失、为空、重复或乱序时，检查器发出诊断。

违规示例。

```text
步骤：暂停作业。
动作：暂停当前作业。
```

合规示例。

```text
步骤：暂停作业。
执行者：值班员。
动作：暂停当前作业。
```

20 个步骤样本中，按块检查检出 11 个结构问题，9 个结构对照均无诊断。全文匹配字段名只检出 2 个结构问题。4 个附有参考框架的合规案例都准确提取了执行者、动作和可选条件。对照也包含结构正确但角色错误的情况。角色是否为真实责任人须对照业务材料。一般叙述和承前省略见角色实验（研发记录，见[发布范围](Validation.md)）。

上述三项规则的逐例报告见语言诊断对照（研发记录，见[发布范围](Validation.md)）。

独立语言保留集有 18 个样本。首次运行检出全部 7 个违规，并把一个「编码错误分类」误判为编码动作。处理该名词结构后，同组回归检出 7/7 个违规，11 个合规对照均无诊断。见初测（研发记录，见[发布范围](Validation.md)）和回归（研发记录，见[发布范围](Validation.md)）。

### RULE-REF-02 补全悬空的回指对象

在受控动作和措施字段中，回指限定词后写出对象名称。对象应有明确的上文来源。

检查器仅在「动作」或「措施」开头的字段行中，诊断直接位于标点或行末前的「该」「上述」。词内的「应该」以及引用、代码字面量不触发。本条只检查该表面结构。多个候选对象之间的指代选择需核对原文。

违规示例。

```text
动作：保存该。
```

合规示例。

```text
动作：保存该请求。
```

本次独立标注覆盖 9 个样本。3 个悬空回指均被检出，6 个对照均无本规则诊断。相同对象名称的补写仍需要来源依据。

## 命题逻辑

### RULE-LOG-01 明确混合条件的组合范围

在同一层组合合取、析取和异或中的两种或更多种连接时，用成对括号标出各组条件。

自动检查适用于以「如果」「若」「当」开头的条件句。条件部分止于第一处未被引文或括号包围的逗号。检查器把「且」和「并且」识别为合取，把「或」和「或者」识别为析取，把「异或」识别为排他析取。同一层同时出现两类或更多类连接词时，检查器发出诊断。以下等价情形可以省略分组。

- 单组包含三个原子谓词，左右结合的真值表相同。检查器逐项比较所有布尔赋值。相同文本的谓词共享一个输入。
- 单组只含合取和析取，且各项谓词文本相同。该结果总与重复谓词取值相同。

违规示例。

```text
如果压力合格或旁路打开且急停可用，启动设备。
```

如果实际要求是始终具备急停能力，使用以下写法。

```text
如果（压力合格或旁路打开）且急停可用，启动设备。
```

### RULE-LOG-02 闭合条件中的圆括号

条件分组使用成对的同类型圆括号。该规则负责括号完整性。分组的真假含义由 RULE-LOG-01 和业务条件共同核对。

检查器识别句首或行首的「如果」「若」「当」。从起始词后扫描至首个未被圆括号包围的逗号或句界。遇到多余右圆括号、全角与半角不配对、未闭合左圆括号，或圆括号内遇到其他类型的右括号时，发出诊断。引文和代码字面量不参加扫描。混合逻辑范围检查也接受这三种条件起始形式。

违规示例。

```text
若（压力合格或旁路打开)且急停可用，启动设备。
```

合规示例。

```text
若（压力合格或旁路打开）且急停可用，启动设备。
```

本次独立标注覆盖 9 个样本。3 个括号错误均被检出，6 个对照均无本规则诊断。括号补齐时，需按原始条件选择实际分组。

## 指令强度

### RULE-MOD-01 使条款标签与动作强度一致

使用强度标签时，在首个主句中使用对应的模态词。

| 标签 | 模态词 | 含义 |
| --- | --- | --- |
| 要求 | 必须 | 主体有义务实施动作。 |
| 禁止 | 不得 | 主体有义务避免该动作。 |
| 建议 | 宜 | 建议主体实施动作。 |
| 权限 | 有权 | 授权允许主体实施动作。 |
| 能力 | 能够 | 主体具备实施动作的能力。 |

检查器定位段落或列表内单行起始的标签。标签后接冒号。若条款先写「如果」「若」「当」条件，检查器跳过该条件和终止条件的逗号。主句检查到句界、下一标签，或逗号后紧随的顺序标记「然后」「随后」「接着」为止。检查器忽略引文和代码中的模态词。检查器避开「把」或「将」引出的受事修饰语，以及「建议」「指出」「说明」等谓词的补语中的模态词。上述判断使用词形和标点线索。遇到复杂句式时，核对主句的实际强度。首个识别出的模态词与标签不符，或检查区间内没有识别到模态词时，发出诊断。

违规示例。

```text
要求：如果工单必须经审批，操作员宜通知管理员。
```

如果通知属于强制动作，使用以下写法。

```text
要求：如果工单必须经审批，操作员必须通知管理员。
```

标注对照报告（研发记录，见[发布范围](Validation.md)）包含 29 个样本。仅搜索标签对应词的基线检出 10/17 个问题，并误报 1/12 个对照。纳入条件范围和词形反例后，检查器检出 17/17 个问题。12 个合规样本均无诊断。

独立保留集初测（研发记录，见[发布范围](Validation.md)）检出 11/13 个问题。漏报涉及权限否定和后续动作借用标记。定位并修复后，同一组样本的回归结果（研发记录，见[发布范围](Validation.md)）检出 13/13 个问题。11 个合规样本均无诊断。该试验包含原文改编和合成样本，验证标签所表达的强度。真实提交前须用来源规则核对条款应具备的强度。

## 数量关系

### RULE-QNT-01 给出非空的同量阈值区间

用明确的上下界和端点关系描述标量的有效范围。上下界共同约束同一个量。

检查器识别「范围」或「阈值」开头的字段。支持同一行两个用「且」「并且」或 AND 连接的比较。第一个比较前可以写量名，第二个比较前可以省略量名或重复同一名称。每个比较用十进制数值。两个界限使用相同单位文本，其中一个为下界，另一个为上界。

支持大于、小于、大于或等于、小于或等于及对应符号。下界大于上界时，区间为空。两界相等且至少一个端点为开端点时，区间也为空。检查器使用 Decimal 比较，满足任一条件时发出诊断。不同单位、不同量、近似关系、单位转换和复合布尔范围超出本条的自动判定语法。

违规示例。

```text
范围：温度大于30摄氏度且小于20摄氏度。
```

合规示例。

```text
范围：温度大于20摄氏度且小于或等于30摄氏度。
```

9 个独立样本中的 3 个空区间均被检出，6 个对照均无诊断。另枚举 128 个上下界、端点开闭及书写次序组合，用独立的有理数取值集合判定是否为空，全部与检查器相符。该试验覆盖已支持的标量区间。近似测量和工程容差应按原文保留。

## 操作呈现

### RULE-DOC-01 在同一警告块列明措施和后果

使用警告块时，把措施和后果分行写明。需要限定适用对象或情形时，在措施前列明条件。

块的首行以「警告」和冒号开头。标题可以跟在冒号后。后续可识别字段的顺序为「措施、后果」或「条件、措施、后果」。每个字段以字段名和冒号开头，字段值写在同一行。空行、标题、下一个警告和新的列表项结束当前块。列表中的警告使用无项目符号的字段续行。检查器在缺少字段、字段为空、字段重复或字段乱序时发出诊断。

违规示例。

```text
警告：机壳温度超过接触上限。
措施：保持防护罩闭合。
```

合规示例。

```text
警告：机壳温度超过接触上限。
措施：保持防护罩闭合。
后果：接触机壳可能造成烫伤。
```

警告结构对照（研发记录，见[发布范围](Validation.md)）包含 18 个样本。仅搜索字段名的基线检出 2/12 个问题，并误报 3/6 个对照。按独立字段和块范围检查时，检出 12/12 个问题。6 个合规样本均无诊断。警告结构检查的结果用于核对信息位置和字段完整性。警告内容须由工程负责人核对。

加入异或后，[三类连接词审计](../results/logic_scope_xor_audit.json)覆盖 972 个生成样本。检查器识别全部 252 个具有不同真值表的条件。其余 720 个样本均无诊断。[五个异或改写案例](../results/xor_pilot.json)覆盖包含式和排他式授权条件、混合条件分组和同类连接。改写后 5 个表达式各有一种真值解释，其中 4 个符合参考表。唯一且错误的改写改变了联锁条件的范围。该审计限于三个原子谓词和四种表示形式。

候选字词见[词表试验记录](Validation.md)。本节的三个连接词在上述受控条件范围内使用。

[可执行操作检查](../results/lexicon_operation_checks.json)复核七种工程差异。SQLite 检查了索引是否用于检索、过滤集合、计数结果、锁释放后的写入以及可重用存储页。OpenSSL 检查了签名后消息是否可验签，并确认改动后的消息不能通过原签名验证。字节前缀和同长度后缀用于区分限定的尾部截断与其他切片。

这些程序检查复核表内定义所描述的操作。自然语句是否符合定义，仍按原文和语义标注核查。定向抽取的 17 个后续语境中，有 4 个符合核准义项，分别涉及回收、过滤和采样。排序式检索优先选择潜在正例，其标签比例用于描述本组样本。

状态语境对照（研发记录，见[发布范围](Validation.md)）保留监测下线、管理下线和实例正常运行的区别。监测端没有收到心跳时，既可能是节点故障，也可能是通信故障。特定系统的状态 ID 应按其文档定义，使用状态名称时保留判定条件。

本次新增三条规则的正反例和枚举结果见[合并验证](../results/merge_validation.json)。合并后不采纳统一禁止代词、把被句、兼类词和所有虚化动词的约束。字数与「的」字计数保留为复核线索。改变句式时核对条件、动作、对象、模态、时序和工具，保留原始事实。

## 可执行性与使用

[规范验收](../results/specification_audit.json)逐条运行规范正反例。九条编号规则均有可执行检查，规范正文通过零诊断检查。该比率按编号规则计算。词典义项、角色真实性和业务条件仍需按规则正文规定的范围核对。

本工具可用 Python 3.9 或更高版本独立运行。日常文档检查仅使用 Python 标准库。

```sh
python3 src/ctc_linter.py 文档.md
python3 src/ctc_linter.py 文档.txt
python3 -m unittest discover -s tests -q
python3 experiments/check_specification.py
```

有诊断时，工具输出文件、行号、规则编号、问题和改写建议，并返回退出码 1。没有诊断时返回 0。文件读取失败时，命令行返回 2。输入用 UTF-8 编码，可以带字节顺序标记。

依存分析实验使用固定的 UDPipe 模型和 Python 包。模型摘要在分析脚本中校验。原始语料和许可信息见[语料说明](Sources.md)。

```sh
python3 experiments/reproduce_public.py
```

复算命令核对随仓库发布的实验报告，并再次运行测试、词表一致性检查和规范自检。外部语料的固定版本及采集方法见[来源说明](Sources.md)。
结构化输出和自举检查使用以下命令。

```sh
python3 src/ctc_linter.py 文档.md --json
python3 src/ctc_linter.py docs/CTC-Specification.md --bootstrap-check --json
```

自举检查把每条规则的反例和正例从规范中提取出来，独立送入同一个检查器。规范说明和全部正例均应零诊断，反例应触发本条规则。反例置于代码块中，普通文档扫描跳过代码块，自举检查另行验证反例。
